# FloodWatch Mock Data (Static GeoJSON Exports)

This directory contains static RFC 7946 GeoJSON exports generated by FloodWatch (Module 2) for offline dashboard inspection and evaluation.

## Files & Data Sources

1. **`flood_extent_groundtruth.geojson`** (822 features)
   - **Source:** SpaceNet 8 flood annotations (Germany AOI).
   - **Provenance:** `observed`
   - **Contents:** Human-labeled ground-truth flooded features consisting of building polygons (`feature_type: "building"`) and unbuffered road centerlines (`feature_type: "road"`). All features have property `flooded: "yes"`.

2. **`flood_extent_predicted_fast.geojson`** (146 features)
   - **Source:** FloodWatch SegFormer-B0 model (`checkpoints_joint`).
   - **Provenance:** `derived`
   - **Mode:** `fast` (whole-tile resize inference, 768px).
   - **Contents:** Vectorized post-event class-1 (floodwater) masks simplified via UTM EPSG:32632 with 9 m² (~50 px) minimum area threshold.

3. **`flood_extent_predicted_accurate.geojson`** (255 features)
   - **Source:** FloodWatch SegFormer-B0 model (`checkpoints_joint`).
   - **Provenance:** `derived`
   - **Mode:** `accurate` (512px sliding-window crop batches with 256px stride).
   - **Contents:** Vectorized post-event class-1 (floodwater) masks capturing fine-grained inundation details.

4. **`zones.json`** (14 demo tiles)
   - **Source:** Deterministically generated by `modules/dashboard/scripts/build_floodwatch_zones.py` using real GeoTIFF footprints and real observed/predicted feature counts.
   - **No Invented Values:**
     * `risk_level`: Strictly `"UNKNOWN"` for all tiles (the dashboard does not score risk).
     * `risk_score`: `null` for all tiles.
     * `observed_flooded_count`: Real integer sum of observed flooded buildings and roads. Sorted descending by this count.
     * `exposed_buildings`: Real integer count of observed flooded buildings from `flood_extent_groundtruth.geojson`.
     * `reasons`: Real counts only (observed building/road counts, fast/accurate model mask pixel counts, training pool status).
     * `needs_survey`, `flooded_percent`, `flooded_area_km2`, `total_buildings`, `accessibility`: Omitted (not in source data).
     * `geometry`: Polygon bounding box extracted from the real GeoTIFF WGS84 bounds in `floodwatch/data/raw/` via `rasterio`. Never hard-coded.
     * `in_training_pool`: Strict boolean per FloodWatch's pool list (`MEASURED.json`). Tiles `0_15_63`, `0_15_68`, `0_15_65`, and `0_20_66` are `false` ("not in the training pool"); all other 10 tiles are `true`.

---

## Provenance Meaning

- **`observed`**: Direct human ground-truth annotations from satellite imagery (SpaceNet 8). Represents verified physical structures and infrastructure affected by flooding.
- **`derived`**: Machine-learning predictions generated by the local SegFormer-B0 semantic segmentation network. Represents model output and hypotheses, NOT ground-truth physical observation.

---

## Critical Training-Pool Caveat

> **Important Honesty Notice:**
> All tiles with flood damage in these export files were in the model's training pool (`in_training_pool: true`). Tiles `0_15_63`, `0_15_68`, `0_15_65` and `0_20_66` were not in the training pool (`in_training_pool: false`) and contain zero annotated flooded features (tested for dry/false-positive response). Agreement between observed and predicted layers is **NOT a held-out test result**. No machine learning evaluation metrics (IoU, recall) are calculated on the frontend.
